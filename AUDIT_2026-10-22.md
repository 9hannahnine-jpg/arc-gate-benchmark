# Measurement integrity audit (2026-10-22)

This branch contains an initial source-code audit, **not** newly reproduced performance results.

## Confirmed harness issues

- The local `AGENTDOJO_TASKS` array has 13 entries and two injection styles, giving **26 attack requests**, plus six benign requests. This is not the 54 attack requests stated in the product README.
- These cases are locally transcribed fixtures, not a full execution of the upstream AgentDojo agent/environment. The observed variable is a gateway block decision, **not** actual unsafe-action prevention.
- `run_injecagent()` is not invoked in `__main__`, so the advertised 198/200 cannot be reproduced by the documented command.
- `arc_request()` treats request exceptions as `blocked=False`. Transport errors must be counted separately, not as model decisions.
- `run_multiturn()` repeats each attack request after scoring the scenario, without incorporating that response into the result.
- The multi-turn scenarios largely reuse the same explicit poisoning text and do not isolate incremental value from session-state detection.
- There are no comparable benign controls in the InjecAgent routine.
- The six benign fixtures are too few to establish a reliable false-positive rate.

## Reporting policy until rerun

Do not publish 100% unsafe-action prevention, 99% InjecAgent detection, or 0% false-positive rate as independently reproduced results based on this harness.

Existing numbers should be labeled **historical, unverified, and from a limited proxy-blocking evaluation** until a corrected end-to-end evaluation is run.

## Required next steps

1. Obtain and pin the exact gateway commit, benchmark commit, model, policy configuration, and upstream dataset revisions.
2. Make failures explicit: BLOCK, ALLOW, ERROR, and INVALID_RESPONSE must be distinct outcomes.
3. Record case IDs, provenance, timestamps, config, and raw responses (with secrets redacted).
4. Run the complete upstream agent environments, observe attempted/executed tool actions, and measure both attack success and legitimate task completion.
5. Evaluate held-out benign cases and report denominators, confidence intervals, and latency distributions.
6. Compare to rule-only, classifier-only, geometry-only, and full-system configurations.
7. Only then update the website and README with reproducible measured figures.

No live API requests or dataset-wide runs were executed during this initial audit.
